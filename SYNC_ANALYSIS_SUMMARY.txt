## KEY FINDINGS SUMMARY

### 1. SYNC PROTOCOL FLOW
   Push (1st) → Pull → Push (2nd) → Finished → Hash Check
   └─ If hash mismatch → Queue sector → Loop back

### 2. CONFLICT RESOLUTION
   Timestamp-based, Last-Writer-Wins (LWW) with deterministic tie-breaking
   - Remote timestamp > Local timestamp → Apply remote
   - Remote timestamp == Local timestamp → Apply remote (deterministic)
   - Remote timestamp < Local timestamp → Keep local, re-queue for push

### 3. ENTITY CHANGE TRACKING
   - Hash: SHA256 of concatenated properties (first 10 chars)
   - Sector: First character of entityId (enables localized recovery)
   - Change ID: 12-char random (idempotency token)
   - Instance ID: Source server identifier

### 4. AUTHENTICATION
   - HMAC-SHA256(documentSecret, ISO8601 timestamp)
   - No persistent tokens
   - Timestamp tolerance: ±5 minutes
   - Sync version compatibility check

### 5. WEBSOCKET UPDATES
   - Transaction-based: CLS collects changes, broadcast on commit
   - Entity ordering: Respects referential dependencies
   - Entity enrichment: Adds data frontend needs (protected content decryption, positions)

### 6. PERFORMANCE OPTIMIZATIONS
   - Batching: 1000 changes per request
   - Pagination: ~1MB per request
   - Sectored verification: O(alphabet size) instead of O(entity count)
   - Content-addressable storage: Hash-based blob IDs prevent duplicates

### 7. SECURITY FEATURES
   - No plaintext password transmission
   - Per-entity encryption with deterministic hash
   - Protected content prefix prevents information leakage
   - Instance identity prevents self-sync
   - Idempotency tokens prevent duplicate application

## IDEMPOTENCY AND DEDUPLICATION

Change ID: 12-char random string
- Checked before applying pulled changes
- Prevents duplicate application of same change
- Works across retries: same changeId = same change

Instance ID: 12-char random per server startup
- Prevents applying your own echoed changes
- Enables multi-master sync (any instance can be sync server)

Sector: First character of entityId
- Enables recovery of partial failures
- 36 possible sectors (0-9, a-z)
- Can resync entire sector without full resync
